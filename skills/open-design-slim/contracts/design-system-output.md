# Design-System Output Contract

This contract applies to portable design-system bundles generated by
`open-design-slim`.

## Required Files

- `manifest.json`: Open Design design-system bundle metadata compatible with
  the repository bundle shape.
- `DESIGN.md`: human-readable source of truth.
- `tokens.css`: semantic CSS variables.
- `components.manifest.json`: machine-readable component inventory.
- `USAGE.md`: instructions for coding agents and maintainers.
- `source/provenance.json`: portable source and validation-gap metadata.

Optional visual files:

- `preview/index.html`: compact visual preview of tokens and components.
- `ui_kits/app/index.html`: app-shell sample for operational interfaces.

## Manifest Rules

`manifest.json` must be valid JSON and should follow the
`od-design-system-project/v1` bundle shape:

- `schemaVersion`: `od-design-system-project/v1`,
- `id`: stable ASCII slug,
- `name`, `category`, and `description`,
- `source.type`: usually `bundled` for this bundle or `local` for host-derived
  copies,
- `files.design`: `DESIGN.md`,
- `files.tokens`: `tokens.css`,
- `componentsManifest`: `components.manifest.json`,
- `sourceFiles.evidence`: `source/provenance.json` when provenance is present.

The manifest is local bundle metadata only. It is not daemon registration and
does not imply the design system was imported into Open Design.

## DESIGN.md Sections

- Intent and audience.
- Color roles with usage, not only hex values.
- Typography roles and fallbacks.
- Layout density, spacing, radius, borders, and elevation.
- Component vocabulary with states.
- Interaction and motion defaults.
- Accessibility baseline.
- Agent usage guidance.
- Provenance and unknowns.

## Token Rules

- Prefer semantic variables such as `--od-surface`, `--od-accent`, and
  `--od-text-muted`.
- Avoid raw color names as the only API.
- Include focus, danger, warning, success, and border roles when the product has
  operational UI.
- State whether tokens are measured, user-provided, copied from the host repo,
  or inferred.

## Component Manifest Rules

The manifest must be valid JSON and should include:

- `name`: system name,
- `version`: local bundle version,
- `components`: array of component records,
- each component record: `name`, `purpose`, `states`, and `tokens`.

## Provenance Rules

`source/provenance.json` must state the source basis and runtime boundary. At a
minimum include:

- `schemaVersion`,
- `bundleName`,
- `sourceType`,
- `sources`: array of source records with `label`, `path`, `role`, and `notes`,
- `runtimeBoundary` booleans showing no daemon, `/api/*`, artifact DB, or data
  root dependency,
- `validationGaps`: array of unverified visual or host-repository assumptions.

## Forbidden Claims

Do not claim the design system was registered in Open Design, published to a
daemon registry, staged into a project database, or connected to a live preview
unless a separate full-runtime workflow actually did that.
